Vault Fantasy · Motion Upgrade

Three primitives,
applied across the app.

The sliding pill, the spring press, and the arc spinner — mapped onto the surfaces Vault already has. Everything below is live: click the tabs, hold the buttons, run the loaders. Every colour is a theme token, so it works in Onyx and Vapor Sky without a second version.

01 · TRAVEL

The sliding pill

Right now every tab in Vault is a hard cut — .la-tab.on::after paints a static underline, .v-ntab.on just swaps a background. One shared element that moves instead of two that blink is the single biggest perceived-quality upgrade available, and it's about 6 lines of JS.

Now Nav tabs — background snaps between buttons
Proposed One pill travels — and morphs width to fit
The width morph is what sells it. Overview → Trade Intel is a big jump in both position and size; because both animate on the same curve the pill reads as one object stretching, not two properties racing. 0.4s is deliberate — fast enough to feel responsive, slow enough that the eye tracks the travel and learns the spatial relationship between tabs.
Proposed The same rail as a 2px underline — for .la-tab strips
Identical mechanics, different skin — so one CSS block and one JS function serve every tab strip in the app: player-stats tabs, results tabs, team-review tabs, the ADP explorer. The glow (box-shadow in the accent) is what keeps a 2px line from looking anemic on a dark surface.

This strip scrolls (Vault's .la-tabs is overflow-x:auto) — narrow your window and try it. The pill is positioned against the strip, so it scrolls with the tabs instead of drifting off them, and clicking a half-visible tab centres it. That only works because offsetLeft and the pill share the same offset parent — put the pill outside the scroller and it desyncs the moment anyone swipes.
Proposed Position filter — the pill picks up the position colour mid-flight
Vault already colour-codes positions everywhere. Letting the travelling pill cross-fade into that colour while it moves ties the filter to the rows it's filtering — you see red arriving before you read "QB". Colour transitions on 260ms, slightly under the travel, so the colour has settled by the time the pill stops.
Proposed Mobile dock — capsule slides, active icon lifts on the spring curve
Two motions, two curves, on purpose. The capsule travels (0.4s rail curve) because it's moving through space; the icon arrives (spring curve) because it's just popping in place. Mixing them up — springing the travel, railing the pop — is what makes hand-rolled motion feel off. 
/* one block, every strip */
.rail{ position:relative }
.rail .pill{
  position:absolute;
  transition: left .4s var(--ease-rail),
              width .4s var(--ease-rail),
              background-color 260ms ease;
}
.rail.noanim .pill{ transition:none }  /* first paint + resize */

/* one function, every strip */
function movePill(rail){
  const pill = rail.querySelector('.pill');
  const on   = rail.querySelector('button.on');
  if (!pill || !on) return;
  pill.style.left  = on.offsetLeft  + 'px';
  pill.style.width = on.offsetWidth + 'px';
  if (on.dataset.c) rail.style.setProperty('--pc', on.dataset.c);
}

The trap to avoid

A hidden strip has offsetWidth === 0. Vault's tabs live inside pages toggled with display:none, so a pill positioned on load lands at width 0 and then visibly snakes into place the first time you open the page. Call movePill() with .noanim inside showPage(), drop the class a frame later, and re-run it on resize and on font load.

02 · FEEDBACK

The spring press

Vault's current press is scale(.97) over 80ms in both directions. It registers, but it returns dead. The upgrade is asymmetry: snap down fast, spring back slow. Press and hold to feel the difference.

Now scale(.97), 80ms both ways
Proposed 80ms down, 500ms spring up
Proposed Scale depth is inverse to element size
0.88 is right for a chip and wrong for a card. Scale is perceptual, not absolute — a 90px chip losing 12% moves 11px and feels crisp; a 600px card losing 12% moves 72px and feels like it broke. Four tokens cover the app: .88 chips · .94 buttons · .975 cards · .99 table rows.
Proposed Where it actually gets noticed — pressable rows
Vault is mostly lists — draft board, ADP explorer, portfolio, free agents. Right now tapping a row does nothing until the modal appears, and on a slow fetch that's a dead beat where the user wonders if the tap registered. A 0.99 press is invisible as a design detail and unmistakable as confirmation. This is the highest-leverage place to spend the spring. 
/* asymmetric — the whole trick is that these differ */
.press{
  transition: transform .5s var(--ease-spring);   /* release */
}
.press:active{
  transform: scale(var(--press-scale, .94));
  transition: transform 80ms ease-out;             /* press */
}
.press.sz-chip{ --press-scale:.88 }
.press.sz-btn { --press-scale:.94 }
.press.sz-card{ --press-scale:.975 }
.press.sz-row { --press-scale:.99 }

Why 1.56 in the curve matters

cubic-bezier(0.34, 1.56, 0.64, 1) — that 1.56 pushes the curve past its endpoint and lets it settle back. The button overshoots its own resting size by a couple percent before landing. You don't consciously see it; you read the button as physical rather than as a rectangle that changed value. It's the same reason iOS buttons feel alive and Bootstrap buttons don't.

One caveat: overshoot only works on transform. Never put a springy curve on width, height, or anything that reflows — you'd be overshooting a layout 30 times a second.

03 · WAITING

Loading motion

There are 20+ loading states in index.html rendered as the text character ⟳ with an inline animation:spin. It's a font glyph — it renders differently per platform, sits off its own baseline, and wobbles as it rotates because the glyph isn't centred in its em box. This is the cheapest-feeling thing in the app and it's everywhere.

Proposed Three sizes, semantic colour
Your spec used #FF8A00 — I'd swap it for var(--accent2). Orange appears nowhere in Vault's palette; it would be the only hardcoded hue in the app and it would fight the Vapor Sky theme badly. Same for the #232326 track → var(--s3). Two arcs on 0.8s linear is exactly right, though — linear is correct here, since an eased spin looks like it's struggling. (Note .vp-wv-spin at index.html:3588 is already hardcoded #e4e6ea/#d50a0a — it breaks in dark mode today and this fixes it.)
Proposed In-button — spinner replaces the label without moving the button
Both states are absolutely positioned inside a fixed-width button, so nothing reflows — the label cross-fades out, the spinner cross-fades in, and the checkmark strokes itself on arrival. This is the pattern for every Sleeper write in Vault: push lineup, submit waiver, accept trade. The drawn checkmark is what turns "the request finished" into "your move landed."
Proposed …but most of these shouldn't be spinners at all
Vault already has .skel and a shimmer keyframe — they're used in the grade strip and nowhere near enough elsewhere. The rule: a spinner is for a discrete action with an unknown wait (connecting, pushing). A skeleton is for content arriving into a shape you already know — player lists, stat tables, league grids. Swapping a centred ⟳ for shape-matched skeletons removes the layout jump when data lands, which is most of what makes loading feel janky.
04 · COMPOUND

Where they stack

The primitives are worth more together than apart. Below: the pill picks the filter, the rows spring on press, and new results rise in on a stagger. Hit Refilter to replay.

Proposed Draft board filter — full interaction
Stagger is 45ms per row, capped at 5 rows. Beyond that the last row waits long enough to read as lag rather than choreography — so on a 200-row draft board you stagger the visible window and let the rest appear instantly. The rise is 10px, not 30: enough to imply arrival, not enough to make the user watch furniture move every time they touch a filter.
05 · SHIPPING

Recommended order

Ranked by perceived-premium gained per line of code touched.

  1. Kill the ⟳ glyph. ~20 inline instances → one .spinner class. Pure find-and-replace, zero layout risk, and it's the most visible cheapness in the app. Fixes the hardcoded .vp-wv-spin colours in the same pass.
  2. Add the two tokens. --ease-rail and --ease-spring next to the existing --ease-out/--ease-sheet in vault-ds.css, plus the four --press-scale steps. Nothing changes visually — this is just the vocabulary the rest depends on.
  3. Spring press on .v-btn and list rows. One rule change in the design system reaches every button; the row press is the one users will feel most on mobile.
  4. Sliding pill on .la-tab first, since that class covers player stats, results, and team review in one go. Then .v-ntab and .v-seg. Watch the display:none / offsetWidth trap in showPage().
  5. In-button spinner + checkmark on Sleeper writes. Smallest surface, but it's the moment where users are most anxious that something actually happened.
  6. Skeletons over spinners for list content — the largest job, best done page by page rather than as one sweep.

Reduced motion

Everything here degrades in one block: pill transitions off (it still positions correctly, it just jumps), presses off, spinners freeze to a static arc at 60% opacity, stagger off. Vault already has prefers-reduced-motion blocks in six places — these should join the global one near index.html:168 rather than adding a seventh.
